# AI Development Artifact Contract

Status: Canonical

Contract version: 1.0.0

Schema dialect: JSON Schema Draft 2020-12

Owner: GDS-DOCS

## Purpose and boundary

This contract is the semantic source of truth shared by GDS Runtime, the AI
Development Orchestration Platform, scoped workers, and execution gateways.
GDS Runtime produces policy; the platform consumes policy and owns operational
state. Consumers may generate versioned bindings but must not redefine meaning.
MCP is an optional transport adapter and is never the contract owner. No shared
schema repository is required before operational evidence justifies extraction.

## Common rules

- All timestamps are UTC RFC 3339 strings.
- All identifiers are non-empty opaque strings. Producers generate them; consumers
  compare them byte-for-byte.
- `repository_id` is the canonical Registry identity and is required whenever a
  package or effect targets a repository.
- An artifact is immutable. A correction receives a new `artifact_id` and points
  to the prior artifact through `parent_artifact_id`.
- An event records an observation or state transition; it is not the artifact.
- Unknown optional fields are retained when forwarding. Unknown required semantics,
  unsupported major versions, invalid enums, missing required fields, and digest
  mismatch are rejected.
- Nullable fields explicitly admit JSON `null`; omission and null are different.

| Event Envelope | State owner / observer | Event store, projections | Deduplicate, then reject invalid transition |

| Execution Package | Policy producer / coordinator | Worker admission | SCW when required context cannot be verified |
| Completion Package | Worker | Reviewer / coordinator | Deduplicate by artifact and execution; never repeat effects |

| Error / SCW Envelope | Any component | Coordinator / human | Route by recoverability and human-decision flag |

Schemas under `schemas/ai-development/` are normative for shape. This document
is normative for semantics.

## Artifact Envelope field contract

The schema defines types and required fields. Identity, schema, timestamps,
producer, classification, content information, digest, retention, status,
metadata, and payload are required. Workflow-scoped IDs are nullable because a
generic canonical artifact can exist before approval or execution. Owners are:
producer for identity/content/digest; governance for schema/classification rules;
operational state owner for workflow correlation. `payload_digest` is lowercase
SHA-256 over JCS-canonicalized payload bytes; `payload_size` is the UTF-8 byte
length of that canonical payload. Digest failure quarantines the artifact.

## Approval and package policy

Approval uses a reference plus immutable scope evidence, not an embedded secret
or credential. An execution package is admitted only when its approval reference
is valid, its repository/branch/HEAD and authority agree, and its content is
self-contained enough for a worker without conversation history. A completion
package reports evidence; it grants no new authority.

Commit, push, tag creation, and tag push are separate effects and approval units.
An effect request binds repository, branch, remote where applicable, expected
HEAD, safe commit set digest, actual diff digest, operation allowlist, expiry,
and an idempotency key. A receipt is the immutable outcome. A push receipt must
include remote reachability evidence when successful.

Tag recommendation is an artifact/event, not an effect. Only an approved
`git.tag.create` request can cause tag creation.

## Identity and correlation

| ID | Scope and lifecycle | Generated by | Retry rule |
|---|---|---|---|
| `q_id` | Governance work unit | Q owner | Stable |
| `repository_id` | Registry-wide repository identity | Registry owner | Stable |
| `approval_id` | One authority unit | Approval coordinator | New when scope is re-approved |
| `execution_id` | One logical execution | Coordinator | Stable across retry |
| `attempt_id` | One worker attempt | Coordinator/worker launcher | New for every attempt |
| `artifact_id` | One immutable artifact | Producer | New for corrected content |
| `event_id` | One immutable event | Event producer | New per observation |
| `effect_id` | One logical external effect | Coordinator | Stable for retry of same intent |
| `receipt_id` | One immutable effect result | Gateway | New per actual attempt |
| `correlation_id` | End-to-end workflow grouping | Coordinator | Stable across workflow |
| `causation_id` | Immediate causing event/artifact | Producer | Points to direct cause |

Actor identity describes who authorized or initiated behavior; producer identity
describes which component emitted the record. They remain separate.

## Delivery, ordering, and failure

Delivery is at least once. Consumers use a durable inbox/outbox, acknowledge only
after durable processing, and deduplicate by envelope ID plus idempotency key.
Ordering is guaranteed only per `correlation_id` when a producer supplies a
monotonic `sequence`; consumers must not infer global order. Lease, heartbeat,
retry budget, backoff, and maximum attempts belong in execution policy/context.

Dead letter is an operational disposition for poison or exhausted messages. SCW
is a governance state requiring missing evidence or a human decision. Either can
cause the other, but they are not synonyms. Prior attempts and receipts remain
immutable. Before retrying an effect, query receipts by `effect_id` and
`idempotency_key`.

## Integrity

SHA-256 is mandatory in version 1 because it is ubiquitous, deterministic, and
sufficient for integrity correlation. Canonical JSON uses RFC 8785 JCS. Digests
are prefixed `sha256:`. Artifact payload, complete request, receipt result, safe
commit set, and normalized diff are independently digestible. Diff digest input
is UTF-8, LF-normalized, Git path ordered, and excludes mutable transport headers.
Changing signed/digested metadata creates a new artifact/request. Large content
uses an external immutable URI plus digest and byte size; partial downloads are
verified before use. Algorithm migration is a new major contract version or a
minor additive multi-digest field followed by major removal of SHA-256.

## Security and credentials

Payloads never contain credentials. A future credential reference may contain an
opaque provider/key identifier only, never a value. Secret detection failure is
`SCW` before publication when scanning is unavailable, and rejection/quarantine
when a secret is detected; automatic redaction is allowed only for a derived
display artifact and never silently mutates canonical evidence.

## Contract decisions

- Canonical ownership: Option B, GDS-DOCS semantic contract and schemas plus
  generated, version-pinned bindings in consumer repositories.
- JSON Schema is used for transport-neutral structural validation.
- Phase 1 negotiation is a declared supported schema ID/major-version set; no
  dynamic protocol is required.
- Reserved future fields are avoided. Phase 3 adds fields through versioning.
- Schema/document drift is prevented by validating all examples and checking the
  required-field and enum inventory in the validation report.

## Existing contract binding

This contract preserves `approval_policy_standard.md`,
`execution_result_evidence_contract.md`, and
`repository_action_status_and_recommendation_model.md` as the semantic owners of
approval classification, required execution evidence, and action status. If a
future conflict appears, those focused standards govern their domain until an
explicit compatibility revision is approved.
